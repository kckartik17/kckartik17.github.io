81. Search In Rotated Sorted Array II

source: neetcode.io
🔗 leetcode.com/problems/search-in-rotated-sorted-array-ii
Return whether target exists in a rotated sorted array that may contain duplicates.
Ex: [3,4,4,5,6,1,2,2], target=1 → true  |  n ≤ 5000, values may repeat   |   Goal → O(log n) avg, O(n) worst
Prereqs: Binary search on rotated arrays • Identifying which half stays sorted • Shrinking search when nums[l]==nums[m] (duplicates)

1. Brute Force easiest

Intuition: Walk the whole array and bail out the moment you spot target. Ignores rotation and duplicates but always works.
  1. Loop through every index i.
  2. If nums[i] equals target, return true.
  3. Finish loop with no hit → return false.
O(n) time · O(1) space
Use when: you need a baseline or the array is tiny.

2. Binary Search optimal

Intuition: One side of mid is always sorted—check if target sits in that range. When nums[l]==nums[m], duplicates block a decision, so shrink l by one.
  1. l=0, r=n−1; while l≤r, m = l+(r−l)/2.
  2. nums[m]==target → true.
  3. nums[l]<nums[m]: left sorted—go left if target in [nums[l], nums[m]), else right.
  4. nums[l]>nums[m]: right sorted—go right if target in (nums[m], nums[r]], else left.
  5. nums[l]==nums[m]: l++ (skip duplicate). Return false if loop ends.
O(log n) avg · O(n) worst · O(1) space
Use when: interview answer—same rotated BS as LC 33 plus duplicate guard.

Dry Run — BS on [3,4,4,5,6,1,2,2], target=1

l=0,r=7,m=3, nums[m]=5≠1

Iter 2
l=4,r=7,m=5, nums[5]=1 ✓
Return
true
Dup case
[1,1,1,1,1,0]: nums[l]==nums[m] → l++ each step
Bounds
Left range: nums[l]≤target<nums[m]; right: nums[m]<target≤nums[r]

Interview Code C++ · Binary Search

class Solution {
public:
    bool search(vector<int>& nums, int target) {
        int l = 0, r = nums.size() - 1;
        while (l <= r) {
            int m = l + (r - l) / 2;
            if (nums[m] == target) return true;
            if (nums[l] < nums[m]) {
                if (nums[l] <= target && target < nums[m]) r = m - 1;
                else l = m + 1;
            } else if (nums[l] > nums[m]) {
                if (nums[m] < target && target <= nums[r]) l = m + 1;
                else r = m - 1;
            } else l++;
        }
        return false;
    }
};
Say in interview: O(log n) average but O(n) worst when all duplicates—l++ linearly skips them. Key diff from LC 33: the nums[l]==nums[m] branch. Mind inclusive/exclusive bounds on each half.

⚠ Common Pitfalls

• Forgetting nums[l]==nums[m] → must do l++.
• Wrong range checks: left uses ≤ on l side, < on m side.
• Claiming strict O(log n)—worst case is O(n) with many dupes.

💡 Interview Tip

Start from LC 33 rotated BS, then add: "when l and m values tie, I can't tell which half is sorted, so I shrink l." Mention average vs worst-case time upfront.
