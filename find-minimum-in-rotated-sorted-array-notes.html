153. Find Minimum In Rotated Sorted Array

source: neetcode.io
🔗 neetcode.io/solutions/find-minimum-in-rotated-sorted-array
Find the smallest element in a rotated strictly increasing array with unique values.
Ex: [3,4,5,6,1,2] → 1; [4,5,0,1,2,3] → 0   |   1 ≤ n ≤ 1000, values are unique   |   Goal → O(log n)
Prereqs: Binary search invariants, rotated-array structure, and careful pointer movement without skipping candidate minima.

1. Brute Force baseline

Intuition: Rotation changes order but not values, so scanning all elements still reveals the minimum safely. It is the easiest to explain and verify.
  1. Initialize answer with the first value.
  2. Traverse each element and keep the smallest seen so far.
  3. Return the tracked minimum.
O(n) time · O(1) space
Use when: interview starts with baseline or constraints are tiny.

2. Binary Search (Segment Check) optimized

Intuition: At any step, one side is monotonic. Detect which half is sorted, discard that half when it cannot contain a smaller value, and keep a running minimum.
  1. Set l=0, r=n-1, ans=nums[0].
  2. If current window is sorted (nums[l] < nums[r]), update with nums[l] and stop.
  3. Pick mid, update ans=min(ans, nums[mid]), then move to the unsorted side.
O(log n) time · O(1) space
Use when: you want explicit handling of fully sorted windows.

3. Binary Search (Lower Bound) optimal

Intuition: Compare nums[mid] with the right edge. If mid is smaller than right, minimum is in left half including mid; otherwise it must be to the right of mid.
  1. Initialize l=0, r=n-1.
  2. While l < r, compute mid.
  3. If nums[mid] < nums[r], set r=mid; else set l=mid+1.
  4. Return nums[l].
O(log n) time · O(1) space
Use when: you want the cleanest invariant-based final solution.

Dry Run — Lower Bound Binary Search on [4,5,0,1,2,3]

l=0, r=5

Interview Code C++ · Lower Bound

class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0, r = (int)nums.size() - 1;
        while (l < r) {
            int m = l + (r - l) / 2;
            if (nums[m] < nums[r]) r = m;
            else l = m + 1;
        }
        return nums[l];
    }
};
Say in interview: We keep the invariant that the minimum is always inside [l, r]. Comparing against nums[r] tells which half still contains the pivot, giving O(log n) time and constant extra space.

⚠ Common Pitfalls

Updating r = mid - 1 when nums[mid] < nums[r] can skip the true minimum at mid.
Comparing mid with left in lower-bound style may break edge cases where the array is not rotated.

💡 Interview Tip

Present brute force in one line, then move quickly to the right-bound comparison invariant. Mention why each pointer update is safe to show correctness confidence.
