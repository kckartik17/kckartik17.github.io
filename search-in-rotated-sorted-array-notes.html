33. Search In Rotated Sorted Array

source: neetcode.io
🔗 neetcode.io/solutions/search-in-rotated-sorted-array
Find target index in a rotated ascending array with unique elements.
Ex: [3,4,5,6,1,2], target=1 → 4   |   n ≤ 1000, unique values   |   Goal → O(log n) time, O(1) space
Prereqs: Binary Search · Array indexing · Rotated array = two sorted segments split at the pivot (smallest element)

1. Brute Force easiest

Intuition: Walk the array left to right and compare each value to the target. Correct but ignores the sorted structure entirely.
  1. Iterate index i from 0 to n−1.
  2. If nums[i] equals target, return i.
  3. Finish loop with no match → return −1.
O(n) time · O(1) space
Use when: sanity check or n is tiny; not acceptable for interviews.

2. Binary Search 2-pass

Intuition: Rotation joins two sorted chunks. Locate the pivot (min element), then run standard binary search on each half until the target appears.
  1. BS to find pivot: if nums[mid] > nums[r], pivot is right; else shrink left.
  2. Pivot splits array into two sorted halves.
  3. Binary search left half [0, pivot−1]; return if found.
  4. Binary search right half [pivot, n−1]; return index or −1.
O(log n) time · O(1) space
Use when: you want to reuse a helper binarySearch function.

3. Binary Search (Two Pass) clean 2-pass

Intuition: Same pivot discovery, but pick the correct half upfront by checking whether target lies in the value range of the right segment.
  1. Find pivot with mid-vs-right comparison (same as above).
  2. If target ∈ [nums[pivot], nums[n−1]], set search range to right half.
  3. Otherwise restrict range to left half [0, pivot−1].
  4. Run one standard binary search on the chosen range.
O(log n) time · O(1) space
Use when: separating “find pivot” from “find target” feels clearer.

4. Binary Search (One Pass) optimal

Intuition: At every mid, one side is fully sorted. Check if target sits in that side’s value range; if yes, search there, else discard it—all in a single loop.
  1. While l ≤ r, compute mid; return mid if nums[mid] == target.
  2. If left half sorted (nums[l] ≤ nums[mid]): target outside [nums[l], nums[mid]] → l = mid+1, else r = mid−1.
  3. Else right half sorted: target outside (nums[mid], nums[r]] → r = mid−1, else l = mid+1.
  4. Exit loop → return −1.
O(log n) time · O(1) space
Use when: interviewer wants one elegant O(log n) solution.

Dry Run — One Pass on [3,4,5,6,1,2], target=1

Start
l=0, r=5 · array [3,4,5,6,1,2]
Iter 1
mid=2, val=5 · left [3,4,5] sorted · 1 < 3 → discard left · l=3
Iter 2
mid=4, val=1 == target → return 4

Interview Code C++ · One Pass

class Solution {
public:
    int search(vector<int>& nums, int target) {
        int l = 0, r = nums.size() - 1;
        while (l <= r) {
            int mid = l + (r - l) / 2;
            if (nums[mid] == target) return mid;
            if (nums[l] <= nums[mid]) {          // left half sorted
                if (target > nums[mid] || target < nums[l])
                    l = mid + 1;
                else r = mid - 1;
            } else {                              // right half sorted
                if (target < nums[mid] || target > nums[r])
                    r = mid - 1;
                else l = mid + 1;
            }
        }
        return -1;
    }
};
Say in interview: “One half is always sorted—I check if target is in that range and discard the other half. O(log n) time, O(1) space. Use <= on nums[l] vs nums[mid] so l==mid works.”

⚠ Common Pitfalls

Use nums[l] <= nums[mid] (not <) — handles l==mid in tiny windows.
Don’t mix pivot-finding logic with target search in two-pass variants.
Test unrotated arrays like [1,2,3,4,5] — pivot should be index 0.

💡 Interview Tip

Start with brute force, then explain the two-segment insight. Offer two-pass pivot+search, then collapse to one-pass once they’re comfortable. Draw which half is sorted at each step.
