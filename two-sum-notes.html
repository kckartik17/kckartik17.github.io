1. Two Sum

source: neetcode.io
🔗 leetcode.com/problems/two-sum
Find two distinct indices whose values add up to target; return smaller index first.
Ex: nums=[3,4,5,6], target=7 → [0,1]  |  [5,5], target=10 → [0,1]   |   2 ≤ n ≤ 1000, exactly one answer   |   Goal → O(n) time, O(n) space
Prereqs: Hash maps for complement lookup • Two pointers after sorting • Single-pass vs two-pass trade-offs

1. Brute Force easiest

Intuition: Try every unordered pair (i, j) with i < j. The moment their sum hits target, you have the answer—simple but quadratic.
  1. Outer loop i from 0 to n−1.
  2. Inner loop j from i+1 to n−1.
  3. If nums[i]+nums[j]==target, return [i, j].
O(n²) time · O(1) space
Use when: n is tiny or you need the most obvious starting point in an interview.

2. Sorting + Two Pointers n log n

Intuition: Sort (value, index) pairs, then squeeze from both ends. Low sum → move left up; high sum → move right down. Map back to original indices at the end.
  1. Build pairs (nums[i], i) and sort by value.
  2. Set i=0, j=n−1; while i<j compare A[i]+A[j] to target.
  3. Equal → return original indices (min first); else move i or j.
O(n log n) time · O(n) space
Use when: you want two-pointer practice or sorted input is already available.

3. Hash Map (Two Pass) linear

Intuition: Pre-load a map value→index, then scan again asking "does target−nums[i] exist at a different index?" O(1) lookups replace nested loops.
  1. First pass: store every value with its index in a hash map.
  2. Second pass: diff = target − nums[i].
  3. If diff in map and map[diff] ≠ i, return [i, map[diff]].
O(n) time · O(n) space
Use when: separating build vs query phases makes the logic clearer to explain.

4. Hash Map (One Pass) optimal

Intuition: For each element, check if its complement was seen earlier; if not, record the current value. Looking only backward guarantees i ≠ j without extra checks.
  1. Keep map prevMap: value → index (empty initially).
  2. At i, diff = target − nums[i].
  3. If diff in prevMap, return [prevMap[diff], i].
  4. Else prevMap[nums[i]] = i and continue.
O(n) time · O(n) space
Use when: you need the canonical interview answer—one scan, one map.

Interview Code C++ · One Pass

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> prevMap;
        for (int i = 0; i < nums.size(); i++) {
            int diff = target - nums[i];
            if (prevMap.count(diff))
                return {prevMap[diff], i};
            prevMap[nums[i]] = i;
        }
        return {};
    }
};
Say in interview: O(n) single pass, O(n) map for complements. Check diff before inserting—avoids using the same index twice. Complement is target − nums[i], not the reverse.

⚠ Common Pitfalls

• Reusing the same index when 2*nums[i]==target.
• Returning values instead of indices.
• Wrong complement: use target - nums[i], not nums[i] - target.

💡 Interview Tip

Walk Brute Force → mention hash map idea → code one-pass. Briefly note sorting is O(n log n) and loses index order until you pair with indices. Exactly one answer is guaranteed.
